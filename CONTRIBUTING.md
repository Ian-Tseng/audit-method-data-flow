# Contributing

Keep changes source-backed, portable, and evidence-bounded.

1. Open an issue describing the scientific-contract or lifecycle problem. Do
   not include confidential manuscripts, reviews, credentials, or private paths.
2. Add or update a deterministic contract test before changing central guidance.
3. Distinguish direct venue requirements, cross-source synthesis, and
   project-specific choices.
4. Refresh time-sensitive first-party source ledgers when their claims change.
5. Run the complete test suite, package verifier, official skill validator, and
   public-sink credential/private-path scan.
6. Update VERSION, both citation files, package version, manifest, and changelog
   together for a release.

Security issues belong in GitHub private vulnerability reporting as described
in [SECURITY.md](SECURITY.md).
